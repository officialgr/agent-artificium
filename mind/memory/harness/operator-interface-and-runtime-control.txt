Purpose

Help an operator use and integrate Artificium from verified local interfaces.
The authoritative human guide is `README.md`; the durable event/client contract
is `artificium-code/REFERENCE.md`. Read the relevant file before giving
exact commands or building a client, because documentation can change.

Process lifecycle

- `python3 artificium.py start` starts the life-loop in the background.
- `python3 artificium.py status` reports a verified `process.alive` value and PID
  alongside context, memory, attention, interaction, scheduler, and sleep state.
- `python3 artificium.py watch` follows the durable life-loop trace. Ctrl-C stops
  watching only; it does not stop Artificium.
- `python3 artificium.py chat` starts or reuses the background life-loop and opens
  a terminal interaction client. Ctrl-C or `/quit` closes that client only.
- `python3 artificium.py stop` is the unambiguous stop command. It first requests
  graceful termination and escalates if the process does not exit.
- In a foreground `run`, the first Ctrl-C requests graceful shutdown; an
  in-flight provider request may finish. A second Ctrl-C forces exit.

Configuration and diagnosis

- `config` prints non-secret configuration; `configure` changes provider/model,
  endpoint, heartbeat, model context window, or native image mode without
  modifying Self or memory. Restart a running process after configuration.
- `key` replaces the saved API key; a running life-loop reloads key changes.
- `doctor` checks layout, credentials, prompt pack, and core state; `doctor
  --live` also makes a real provider request.
- Setup has first-class `ollama` and `vllm` providers. Their normal local URLs
  and model IDs are discovered automatically, and no fake key is required for
  an unauthenticated server. `custom` accepts any other OpenAI-compatible root,
  `/v1` base, or full chat-completions URL. Read the README's local-model
  section before giving exact launch or context-window commands.
- Artificium uses textual tools rather than provider-native function calls, so
  local-server native tool-call parser flags are not part of its contract.
- Provider requests print a request ID, delayed-wait notices, elapsed completion
  time, and an exact model-log path on failure. Exact request/response evidence
  is under `logs/model/`; `logs/lifetime.jsonl` and feature logs hold runtime
  evidence.

Clients and interfaces

Use `ArtificiumClient` or the documented JSON event shape rather than bypassing
the interaction boundary. A reusable chat UI, screen observer, sensor, or agent
bridge belongs below `mind/tools/`; an entity's ordinary product belongs below
`mind/space/`. Build a text-only send/poll loop first, prove notification
reconciliation and thread isolation, then add attachments, rendering,
authentication, or richer presentation. A client is not the agent process and
must present their lifecycle separately.

Exactness habit

Never guess commands, config fields, attachment behavior, or event schema when
the repository documentation can answer. Read the current guide, cite the local
path to the operator, and preserve any verified recurring troubleshooting
lesson by updating this memory or the appropriate harness/tool memory.
